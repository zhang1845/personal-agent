# Daynest · AI 个人工作台 v0.8.1

Daynest 将日程、待办、项目资料和个人记忆集中到一个支持自然语言交互的个人工作台。前端使用原生 HTML/CSS/JavaScript 与本地 Bulma 1.0.4，后端使用 Python、SQLite 和 nanobot Python SDK。没有 npm 构建步骤，不安装 Ollama 或本地大模型。明确指令仍可离线使用；复杂请求在你配置并启用 API 后交给真实 nanobot 工具循环。

项目对外名称统一为 **Daynest**。现有 Python 包名、命令、GitHub 地址及数据目录沿用原有标识，升级可直接复用已有配置。

## 启动与停止

旧版启动和停止脚本继续可用，以下使用 Daynest 命名的新入口。

支持 macOS 与 Windows 本机使用。Windows 10/11 x64 使用 Python 3.12，完整步骤见 [Windows 使用说明](Windows使用说明.md)：先双击 `安装依赖.cmd`，再双击 `启动Daynest.cmd`；通过 `停止Daynest.cmd` 停止。Windows 首次安装与双击流程仍需实机验收。

以下为 macOS 命令，在项目目录运行。不要跨系统复制 `.venv`。

双击 `启动Daynest.command` 打开 [工作台](http://127.0.0.1:8787)。服务在后台运行，关闭终端或浏览器不会停止；双击 `停止Daynest.command` 停止本项目服务。电脑休眠、关机后不能继续执行计划，没有配置开机自启动。

```sh
.venv/bin/python code/manage_service.py start
.venv/bin/python code/manage_service.py status
.venv/bin/python code/manage_service.py stop
```

新电脑使用 Python 3.11 以上，建议 3.12，先安装依赖。依赖来自公开开源项目；下载依赖会联网，不会下载推理用的大模型。SDK 的部分依赖带有文件类型识别运行库，本项目直接调用文档转换器，不启动本地 LLM。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
```

需要前台调试或隔离数据时：

```sh
.venv/bin/python -B code/run.py web --port 8788 --data-dir /private/tmp/daynest-test
```

## v0.8 检索与反馈

“资料库”现在按约600字、100字重叠划分资料，使用本机 BM25 排序并按资料去重；项目隔离、原文与个人想法区分保持不变。助手引用可查看生成时的片段与原文位置，修改或删除原文不会改写历史摘录。没有新增向量模型、下载或外部检索接口。

助手回复下可标记“有帮助”或“有问题”。“评测与反馈”保存原问题、回复、引用快照和可用的处理记录关联；人工填写原因、改进措施与复测结果后关闭问题。反馈可转为检索用例，必须人工确认预期资料；不会把本次命中结果当作正确标签，不会自动训练模型。

用例支持项目范围、预期命中的多条资料、无相关资料负例、人工参考答案、编辑与停用。离线评测同时运行原关键词检索与分段BM25，在同一份资料和用例快照上比较 Top-K 命中率、预期资料覆盖率、MRR 和负例空结果率；分母为零显示暂无样本。正例必须命中所有预期资料才算该题通过。报告保存版本、摘录及时间，支持查看最近10次和导出 JSON。资料修改/移出/删除会要求复核预期标签；旧报告保留并提示快照已过期。

检索指标不等于模型回答准确率；参考答案不参与自动打分。单次离线评测最多50条启用用例、500条资料，Top-K 为1–10。反馈处理与改进仍由人工完成。所有功能沿用本机存储、原生前端和既有依赖。

可独立运行自编固定示例集（12例），只使用临时数据库，不给正式资料库填充样例：

```sh
.venv/bin/python -X utf8 -B code/quality_benchmark.py --output output/retrieval-benchmark.json
```

示例集用于可重复检查方法，不代表个人资料效果、真实用户收益或端到端模型问答正确率。正式页面初始没有用例或效果数据，须由你确认预期资料后再评测。

## v0.7 聊天入口

现有链接、文件、提醒和外部日历能力已接入聊天，共 29 个受限工具。基础指令无需模型；跨功能分析与多步骤请求需要配置并启用 API。

| 需求 | 示例 | 实际行为 |
| --- | --- | --- |
| 链接归档 | `导入 https://example.com/article，保存到资料库` | 只读取本条消息明确提供的公开链接，展示正文预览，确认后归档 |
| 文件归档 | 在助手输入区上传文件，再发送 `导入附件` | 支持 PDF/DOCX/PPTX/XLSX/TXT/MD，每个8MB、每条消息最多5个；原文件不落盘，只保留有界解析文本 |
| 一次性提醒 | `明天15:00提醒我整理材料` / `20分钟后提醒我休息` | 生成待确认计划；默认工作台消息，已配置外部渠道时会在确认卡中说明 |
| 每周提醒 | `每周一到周五09:00提醒我签到` | 精确保留星期范围、时间和内容，确认后启用 |
| 只用工作台 | `明天15:00提醒我整理材料，只在工作台提醒，不要发外部通知` | 持久保留该计划的仅工作台限制，即使全局通知后来开启也不外发 |
| 管理提醒 | `查看提醒` / `暂停喝水提醒` / `删除喝水提醒` | 查询实时计划；修改和删除先生成草案 |
| 改期、查空闲 | `把明天的方案评审改到16:00` / `查找明天30分钟的空闲时间` | 先按日期和标题定位，歧义时澄清；改期保留时长并在确认时校验版本与冲突 |
| 日历同步 | `同步今天的日历` | 使用已保存且启用的账号；先展示范围与读写模式，确认后执行，不会自动开启外部写入 |
| 多步骤 | `读取 https://example.com/article 然后归档，并根据内容生成待办草案` | 启用 API 后由真实 nanobot 循环调用工具，所有保存和同步仍需确认 |

附件和网页预览绑定到当前对话及关联项目；上传和读取不等于归档。超过12000字时，只保存明确展示的截选内容，确认界面必须单独勾选。历史预览可以回看，助手不能读取任意电脑路径。保存使用服务保存的原文，不接受模型编造正文或代替用户勾选。

否定和只读要求会限制写草案；复合请求优先交给模型，未启用 API 时会明确要求拆分，不会只完成其中一步却声称全部完成。具体某一天/某场会议的提前提醒不会扩大成长期全局计划。一次性提醒按确认时刻执行，日程改期后需要另行调整；到时超过5分钟仍未运行则结束，不再补发。每天/每周计划仍需要电脑醒着、服务运行。

同步和提醒草案绑定已确认的配置/时区；设置变动后要求重新确认。保存、创建提醒和同步有持久化确认记录，重复确认不重复执行；崩溃或远端结果不明时禁止自动重发。尚未配置真实 API / 日历 / 通知的能力不会显示为已连接。

## 既有工作台能力

| 功能 | 使用入口与实际行为 | 边界 |
| --- | --- | --- |
| 链接归档 | 资料库 → 导入链接；Trafilatura 提取标题、正文、来源，预览后保存并关联项目 | 只读公开 HTTP/HTTPS 网页，最多 2 MB；登录页、反爬及依赖脚本的页面可能失败；拒绝内网地址和不安全重定向 |
| 文件导入 | 资料库 → 保存资料 / 导入文件；MarkItDown 解析 PDF、DOCX、PPTX、XLSX，也支持 TXT/MD | 最大 8 MB；先预览，保存正文而非原文件；扫描件 OCR、加密文件不支持；超过 12000 字必须明确确认截选内容 |
| 定时摘要与提醒 | 自动化 → 定时计划；APScheduler 每 30 秒检查，SQLite 保存计划与发送去重记录 | 个人时区、每日安排/到期待办摘要、日程提前提醒；可暂停/删除；服务需持续运行，错过不补发 |
| 重复日程 | 新建日程 → 重复；日历直接展示每次实例 | 每天/每周/每月，间隔 1–12；次数上限 366 或两年内截止；支持仅本次/整个系列修改取消 |
| 真实日历 | 自动化 → CalDAV 日历；测试账号、选择日历，确认后手动同步 | 默认关闭，先只读；需自己提供协议兼容服务及账号；双向写入需额外勾选；远端重复实例只读，本地重复系列暂不推送 |
| Agent 多步执行 | 设置 → 模型 API；配置后发送复杂请求 | nanobot-ai 0.3.5 SDK 真实工具循环，最多 8 轮，模型循环超时180秒（正在进行的底层读取可能需等待连接超时）；显示模型和工具执行步骤；所有写入先生成草案，应用后生效 |

源码不包含模型 Key、CalDAV 账号或外部通知地址，需在本机自行配置。自动回归使用真实解析器、nanobot SDK 与模拟网络；真实模型的本机联调不能代替其他服务商、日历账号或手机通知的验收。

## 模型 API 与 Agent

日程支持“今天下午两点，时间两个小时，名称为学习”“一小时半”“两个半小时”等自然表达。未接模型时只追问缺少的信息；启用 API 后，规则无法完整理解的日程请求和补充回答会交给模型结合本次对话处理，不要求固定句式，不擅自补上缺少的时长。写入仍需确认。

普通日程的修改和取消兼容模型传入的 `scope: occurrence`，与省略范围参数相同，仅处理指定日程；普通日程仍拒绝 `scope: series`。确认、最新版本校验及重复请求保护继续生效。

“设置 → 模型 API”填写 API 地址、Key、准确模型名称。目前支持 OpenAI 兼容 Chat Completions，远程要求 HTTPS，本机回环可使用 HTTP。保存不会联网；“测试已保存配置”发送小请求，不带个人资料。勾选启用后，复杂请求会发送必要的对话、已保存记忆、工作方式和相关资料，费用按服务商规则计算。

Key 留空保留，勾选清除后保存可删除；更换 API 地址时需重填或清除旧 Key。Key 保存在本机明文文件（POSIX 为 0600；Windows 继承目录访问权限），接口只返回是否已保存。没有自动重试、备用供应商或收费回退。需要服务商模型支持工具调用；未配置时继续规则和本地关键词检索。

可以离线尝试“今天有什么安排”“明天15:00 方案评审30分钟”“待办：整理材料”“记住我喜欢简洁表达”。涉及重复或多步骤的表达交给已启用 API，避免被规则误建为一次日程。未启用 API 时可使用结构化表单。

复杂请求例如“根据这个项目的资料，整理推进步骤并生成待办草案”。SDK 仅注册工作台已有的日历、资料、任务、记忆、导入、提醒及同步工具，移除了上游默认 shell、任意文件读写和子 Agent 工具。项目对话限制资料范围；回复引用保存的标题、版本及摘录。执行记录显示真实请求/工具名称，供应商返回用量时才显示 token。中断时保留已有草案，尚未应用的草案不算执行完成。

工作方式、原文和个人想法独立保存。没有启用上游渠道、Dream 自动记忆、自带 WebUI、整目录扫描或无限自主执行。嵌入式 SDK 不依赖另起 nanobot gateway；网页服务就是本项目的宿主进程。

## 日历、任务与同步

月/周/日视图、全天和跨天日程、冲突检查、查找空闲、ICS 快照导出均保留。任务支持编辑、到期筛选排序、回收站及恢复，可确认占用候选空闲时间；加入日程不会自动完成任务，修改或删除任务不会改变日程。普通写入与重复系列共享持久化请求去重，同一请求 ID 不得用于不同操作。修改取消需要最新版本。

重复安排使用日程的 IANA 时区保持本地钟点；遇到夏令时跳空/重复会拒绝整个创建。每月不存在的日期跳过。修改整个系列会按初始规则重建并清除已有单次例外，页面和草案明确提示。本次修改/取消不会扩大到整个系列。ICS 导出是指定范围内的实例快照，不是云同步或重复规则订阅。

CalDAV 配置服务地址、账号、应用专用密码，保存后测试连接并选择日历，再启用手动同步。账号和所选日历有独立映射，切换账号不会重放其他账号的操作。单次同步最多 31 天/200 条，以结束日期不含处理。

先只读核对。勾选允许写入后，确认同步会推送所选范围的本地单次日程及已同步日程的修改/删除；界面提示影响范围。UID、ETag 与条件请求保护修改，冲突可明确选择本地或远端。远端搜索缺失不直接认定删除，先 GET 核查；重复实例的移除核查完整资源的展开结果。导入不自动挪走相冲突的安排。

超时或断线可能已在远端写入，记录为“结果待核查”。界面“只核查结果”只发读取请求，不重发；未核查前阻止该资源再次导入/写入。复杂远端 RRULE、无时区或无 ETag 等情况可能拒绝处理，需要回原生日历。未实现 Google/Outlook 专用 OAuth 或多账号自动轮询；需按服务商实际 CalDAV 支持判断。

原有 stdio MCP 与外部桥接仍可用，`assets/bridge.example.json` 描述外部命令、字段映射和独立 profile_id。外部后端必须提供完整区间、稳定 ID/版本及含偏移时间。CLI 例子：

```sh
.venv/bin/python code/run.py tool calendar_list_events --args '{"start":"2026-10-27","end":"2026-10-28"}'
.venv/bin/python code/run.py mcp
.venv/bin/python code/run.py export --start 2026-10-27 --end 2026-10-28 --output output/my-day.ics
```

## 提醒和通知

创建每日安排摘要、到期待办摘要或日程提醒计划后，勾选启用。摘要使用真实本地日历/任务计算，不调用模型；无 API 仍能运行。日程提醒跳过全天事件，按计划的提前分钟统一提醒，不代表写入原生日历 VALARM。

默认只进入“自动化 → 工作台消息”。要发外部通知，自己填写 Apprise 支持的地址并启用；地址可包含私密 token，保存后不回显。测试会发一条你主动确认的消息。邮件、Webhook 等需对应服务可用，供应商可能收费；项目不代办账号或购买服务。

成功状态只表示渠道接受请求，不能保证手机已展示。发送失败或不确定不自动补发；重启后不重试已发请求，排队超过五分钟的记录只保留为过期消息。没有 OS 通知权限配置、微信个人号自动化或短信通道。服务休眠/关闭时不运行，恢复后错过时刻不补发。

## 资料与数据

保存前展示解析结果和可能重复的来源；同项目相同正文会拦截重复保存。单条正文最多 12000 字、个人想法最多 2000 字，超长导入明确提示并需要确认截选。保留项目关联、独立想法、关键词搜索、历史引用；不是向量语义搜索。网页抓取拒绝 DNS 返回的内网地址。当前代理可能返回 198.18/15 假 IP，此时可在导入窗口明确勾选“代理假 IP 时使用公开 DNS”：仅向 Cloudflare 发送域名并核验公开结果，固定连接到核验 IP；不发送路径、正文或凭据。选项默认关闭，不放宽内网校验。

数据位于 `output/runtime/`：原有 `calendar.sqlite3`、`assistant.sqlite3`、`knowledge.sqlite3`，新增自动化、CalDAV 映射/操作记录、Agent 执行记录数据库，以及私密配置和受限 SDK 工作目录。升级前已备份旧数据；迁移或备份前先停止服务，整体保留这些文件；Windows 迁移步骤见使用说明。没有云备份、加密保险箱、多用户登录或公网访问。运行日志为 `output/service.log`。
