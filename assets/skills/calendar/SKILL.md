# Daynest · 个人日程

首次操作先调用 `calendar_status`、`calendar_get_preferences`，需要时列出日历。状态若是本地开发模式，明确告诉用户这里保存的是本机测试日程，没有接通云端和手机提醒。不得把本地写入当成已同步 iCloud、飞书、Google 或 Outlook。

## 日期与对象

将相对时间按工具返回的当前时间和用户时区转换成明确的 ISO 日期与时间。缺少标题、时长或具体日期等必要信息时才补问；用户已明确的安排直接执行，不重复要求确认。工具不可用、时区未知或存在夏令时歧义时，不猜测写入。

查询当前安排必须调用工具，不依赖对话记忆。创建或改期交由工具检查冲突，不通过其他文件或未经校验的底层接口绕过检查。寻找空闲时段先用 `calendar_find_free_slots`，展示具体日期和时段；用户选择后再新建。

修改或取消先读取精确事件 ID 与最新版本。用户只说“那个会”且有多个匹配时，列出候选再澄清。不要随意选择同名事件。用户未明确要求时不邀请其他人、不移动其他会议、不扩大到整个重复系列。版本过期时先查询新的事件，不直接用新版本重放旧操作。

## 执行与重试

每次新建、修改、取消生成唯一 `request_id`。同一操作重试沿用原编号和完全相同的原始参数，不通过换编号绕过去重。结果未知时按工具提示核查，不重发，不声称成功。

只有工具成功返回才报告已经完成。回复包含规范化日期、起止时间、时区、所属日历和事件 ID。工具报错时说明具体失败、是否有变更及用户可采取的下一步。查询失败不代表无安排。

本地后端不发提醒；只有真实后端声明支持提醒并已成功写入时，才能说已设置日历提醒，不能声称消息已送达手机。

## 偏好与预算

只保存用户明确表达的时区、工作日、工作时段、午休和缓冲设置；不把临时会议保存为长期偏好。允许用户查看和更正。

模型只使用本机 Ollama，不启用收费云模型或 fallback。停止或不可用时明确说明，不自行购买服务或用免费试用替代预算约束。实际关闭 Ollama 云能力需在 Ollama 服务环境中配置 `OLLAMA_NO_CLOUD=1`，不是只在 MCP 进程中设置。

本 Skill 不能替代程序校验。真实日历账号授权、手机通知和本地模型质量仍需分别验证。
